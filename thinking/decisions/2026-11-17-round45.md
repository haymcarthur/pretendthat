- **Date:** 2026-11-17
- **Decided by:** Haylee (decisions/2026-11-17-printables-library.md: the five recommendations and her five answers).
  How it was built is Claude's call, noted below.
- **Spec:** research/2026-11-17-printables-library.md, design/printables-library/index.html.
- **Pictures:** /tmp/pt-round45/pages/ (every type and layout, both sets, fixture art, no AI: `contact-sheet-color.png`,
  `contact-sheet-outline.png` + one PNG per page) and /tmp/pt-round45/live/ (the two live kits).

## 1. Picture-only art (fixes the double frames)
- Every new kit image ends with `KitArtPrompt.pictureOnlyRule`: no words, letters, numbers, frames, borders, card /
  badge / ticket / sign shapes, banners, labels or blank boxes; just the picture on white. The badge sheet is now
  6 **characters** (waist up, dressed for the job), not 6 badges. Nothing asks the model to spell anything.
- The app draws the card, its border, the title, the role title, the "Name: ____" line, numbers and every word in
  its own space beside the picture (`PretendThat/Print/LibraryPages.swift`, reached from `KitPageView` when
  `KitItem.variant` is set). The art sits in its own box; text never sits on it.
- Tickets: every copy has its own number drawn by the app (boarding 1A 1B … 2D, admission 001 … 008, keycard
  Room 101 …; `PrintLibrary.copyNumber`). Clue and mission cards are numbered 1, 2, 3 … and each prints once.
- Badge sheet sliver: the slicer now drops a small strip of ink touching a cell edge (a neighbor leaning over) and keeps
  a drawing in two parts (`CutoutSheet.mainInk`, used for badges and cut-outs; tested).
- Scene rows' role characters: a picture-only badge slice IS the character (no banner crop).

## 2. The library: 17 types, layouts drawn by the app
- `KitRecipe` has the original 6 + order slips, map, clue cards, mission cards, log, medals, stickers, passport,
  labels, code decoder, control panel (`PrintLibrary`: what each is for Claude, its verbs, its nouns, line limits, art).
- Layouts (`KitVariant`): badge lanyard / round pin / ID card; sign door / hanging banner / marquee; money bills /
  coins / tokens; tickets boarding pass / admission / keycard (or appointment card with a Time line); menu card /
  board / show program; log ruled / tick chart. The rest have one layout. Color set = soft tints on the app's frames;
  outline set = white frames; text and lines always black.
- **Art per printable (Haylee's answer 2: one picture per printable):** each printable is at most ONE image call per
  set: a single picture (sign's place, map, money emblem, ticket, log header, passport cover, control panel window) or
  one sheet of small pictures the app slices (menu dishes, order slips, clue hints, missions, medals, stickers, labels).
  Badges = the character sheet, cut-outs = the cut-out sheet (unchanged), the decoder = none (SF Symbol alphabet).
  Claude's call: order slips get their own sheet rather than borrowing the menu's (simpler, same as "one per printable").
- **Layout choice (app, not Claude):** family default (crews → ID card, adventures → pin, workplaces → lanyard; shows →
  marquee / program / tokens…) plus each game's preferences, filtered by what the item says (a "Boarding Pass" is a
  boarding pass, a list with no prices is a program), then the first one not used in the last 3 kits
  (`RecentPrintMemory`, "type.variant" ids only in UserDefaults, nothing about kids). Tested: 3 pirate games → pin,
  lanyard, ID card. Live: the restaurant after the treasure hunt got lanyard and bills (the hunt had pin and coins).

## 3. Per-game shortlists
- `PrintShortlist.games`: all 42 suggested games plus spy and superheroes, 4–6 types each from the research table,
  badges first, no sign where there's no place (treasure hunt, spy, detective, rocket, submarine, camping, dino dig,
  bird-watching, mail route, weather, superheroes). Matched from set_game's game type first, then the title; the game
  named first wins ("Pirates in Space" → pirate ship). A made-up game gets the whole library.
- The kit-pages prompt (`Prompts.libraryRules`) gives the shortlist (or "made up: choose freely"), up to 2 swaps for the
  twist, "every printable has a real job (wear, hang, pay, show, punch, hide, find, decode, stamp, tick, give)", the
  library, picture-only art, very few words, and that Nutmeg reads clue cards, mission cards, logs and order slips out
  loud. The guide prompt adds a read-aloud rule when the kit has those types.

## 4. Wiring
- `Sanitizer.libraryItems`: one per type, badges first (app-written if missing), no sign without a place, ≤ 2 types off a
  known shortlist, 4–6 items (topped up from the shortlist), id = type, lines/words clamped, $1 money, $1–5 prices,
  pictures never prices, image budget ≤ 6 per set, ≤ 7 pages. `Validate.pages` asks once (badges, count, duplicates,
  sign, shortlist) before that. Idempotent.
- Setup / clean-up: every new type has its fallback jobs and row nouns; coverage keys are `page:<item id>` (= its type,
  so older kits' `page:<recipe>` keys still match). Tested 1–6 players on 6 library kits: every printed item is in a
  setup row and a clean-up row (badges in the openings). The guide's `pageJobs` schema lists THIS kit's types.
- No printed props: a prop may never be one of this kit's printables by its title or kind (a rocket kit's control
  panel); new global words (medal, slip, clue, logbook, decoder, booklet, blueprint). The retry names this kit's pages.
  Realtime instructions: one sentence changed (the list of paper things), nothing else.
- Guide repair accepts the new printables' words in tasks (a "clue card" isn't turned into a pretend thing).
- Saved games: schema 4; `KitItem` decodes an unknown type or layout name as nil (never a failed load); the new fields
  are only encoded when set, so schema-3 games encode and replay exactly as before (old art, old layout, no images).
- The bundled airplane game is now a library kit (ID-card badges, door sign, bills, boarding passes, menu card).
- Kit progress lines: a general "pages" topic for the new types ("I'm drawing more pages for your game!").
