# Setup builds areas; every printout gets used in the scene (Haylee's idea, 2026-11-21, not built yet)

**Haylee:**
- Setup should build the play space by AREA: a spaceship = cockpit, engine area, passenger area; a restaurant = kitchen, dining area, host stand, entrance; a treasure hunt = hide the treasure, pick a starting point, put supplies in places. All using the props and printouts.
- The scene ignores many printouts (space action cards, the captain's log, a travel game's passport). Badges, signs, menus and money get used; others don't. Whatever we print should be used during play.

**Claude's take:**
- Areas: yes. Each area has an owner role (captain → cockpit), so ownership and fair jobs come naturally. Props and printouts are placed in an area, and events can point at areas ("the engine room is beeping!"). 2–4 areas, merged for 1–2 kids.
- Printouts: give every printable TYPE a "play job" (like the prop stand-ins): action cards = draw one in a calm stretch and act it out; captain's log = write or check off what happened; passport = get a stamp at each stop; tickets = hand over to board; map = used in a navigation event. Code check: every printout is used in the opener, an event or a calm-stretch idea (wearables like badges are covered by setup).
- Add short calm-stretch "ideas" between events (no chime; "While we fly, Captain, write in your log what you saw"), so quiet time has a nudge and the printouts get used.
- Cost: slightly bigger guide (~+0.5¢). Do it after the current round.

## Decided (Haylee, 2026-11-21): yes, and the bigger goal is that everything flows
"Right now they all seem fragmented. Sure they all share the same theme… but none of them work together. I want them all to seem intentional and like they belong together."

**Claude's take on the root cause:** the pieces are written separately today (the kit is chosen first, the guide writes the pages' jobs, each found prop is "woven" in by its own call, then repairs patch the gaps), so nothing knows the whole game. Fragmentation is built into the pipeline, so more rules won't fix it.

**Plan (next round after the current one):**
1. **One game plan first.** One AI step writes the whole world: the story, 2–4 areas (each with an owner role), and every object (found props and printouts) with its life cycle: which area it lives in, who owns it, the moment it's used in the scene, and how it's put away. Setup, events, calm-stretch ideas and clean-up are all derived from that plan, so they reference the same things.
2. **Printouts are chosen for the plan.** Each printout exists because the plan uses it (the log is written in after events, the passport is stamped at each stop). No printout without a use.
3. **A traceability check in code:** every object has area + owner + a use in play + a put-away step; every area is built in setup and appears in at least one event. Failing items are repaired or dropped, never shipped unused.
4. **Setup cards by area** ("Captain: build the cockpit", 2–3 items), merged for 1–2 kids. Mockup first.
5. **Calm-stretch ideas** between events (no chime) that use the printouts.
6. Cost target: about the same per game (one bigger planning call can replace the per-prop weave calls); measure it.
